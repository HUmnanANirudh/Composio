          The agent's route

          A Python pipeline gathers the sources and checks every answer. Composio provides the catalog cross-check and web search, through a Platform SDK session to Exa. The reading step for these 100 records was done by Claude in a Claude Code session, from the same source packs an LLM would get. LLM API free tiers could not finish an unattended run (details under “Where it fell short”). Square stations are where a human had to step in.

          Where a human was needed

          • Catalog matching. Fuzzy name matching mapped 80 of 100 apps cleanly; 20 ambiguous ones (Zoho CRM → ZOHO, GoHighLevel → HIGHLEVEL_LOCATION, Mermaid CLI → none) are pinned in a reviewed override file.
          • Search credentials. Composio's built-in search toolkit is retired (HTTP 410), so a human created an Exa key; research connect-search registers it on the agent's Composio user. Without it the agent prints a Connect Link and runs crawler-only.
          • The answer key. 20 apps × 6 fields read from vendor docs, with URLs and quotes. Contested fields are left unscored rather than guessed.
          • The reading step. Groq’s daily caps and Gemini’s free-tier limits stopped the unattended LLM run, so the user chose to have Claude read the source packs in-session. The pipeline still gathered every source and re-checked every quote.
          • Reviewing misses. Each miss is read against its source and given a verdict (agent wrong, key wrong, or ambiguous) in data/audit.json, one record per app and field. The key was wrong three times (Clay, SendGrid auth, Harvest MCP); each correction is logged with its source.

          Run it yourself

          From GitHub: Actions → Run research agent → Run workflow, type any app from the list. The job summary prints the cited record and uploads the JSON. Or locally:

          uv sync && cp .env.example .env    # COMPOSIO, EXA (+ GEMINI for the automated path)
uv run research connect-search      # Exa → Composio user
uv run research pack --apps Attio   # gather sources: crawler + Exa
# read data/packs/004.md, write cited answers to data/manual/
uv run research ingest --apps Attio # grounding + rules, re-research flags
uv run research finalize            # apply fixes, re-check, final records
uv run research run --apps Attio    # or: fully automated, Gemini extracts
uv run research evaluate            # score vs answer key
uv run research build-site          # this page's data

          Where it fell short

          • LLM API free tiers could not finish an unattended run: Groq caps each model at 200K tokens a day, and on a free Gemini key the Pro models are capped at zero and the Flash models were overloaded for hours. The 100 records were extracted in-session by Claude instead, from the same source packs.
          • The extractor also wrote the answer key, so the sample is not an independent grader and 97% is an upper bound. The key was drawn before any extraction, and every miss, key correction and source is published so anyone can re-check it.
          • One app could not be identified: the sources for “Paygent Connect” describe several unrelated products named Paygent, none of them NMI-powered.
          • JavaScript-rendered docs (e.g. GoHighLevel's Stoplight portal) return almost no text to a plain fetch.
          • “Access” is the hardest field: pricing pages rarely say plainly whether the API is on the free plan.
          • The answer key covers 20 of 100 apps; the other 80 rely on the loops and confidence alone.
