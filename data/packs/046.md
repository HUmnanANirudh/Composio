Authentication and permissions
To keep Squarespace merchant site data private and secure, every request to Commerce APIs must be authenticated and have minimum permissions. However, authenticated requests automatically have access to public site data, such as site name, identifier, language, currency, time zone, and location.
Read the permission levels for each Commerce API below. Then, depending on your development needs, authenticate requests by using an API key or OAuth access token.
Remember: Requests only have access to data for the website that owns the API key or OAuth access token.
API permission levels
Forms API
- Read Only: View form submission data; for Zapier integration only
Inventory API
- Read Only: View inventory stock levels
- Read and Write: Manage inventory stock levels
Orders API
- Read Only: View order, fulfillment, and customer information (name, email, address, and more)
- Read and Write: View customer information (name, email, address, and more); manage order and fulfillment information
Products API
- Read Only: View product information, including information for any images and variants; view Store Page information
- Read and Write: Manage product informatio

Announcing Self-Service OAuth Credential Management
Date: Monday, July 27, 2026
Starting Monday, July 27, 2026, Squarespace is transitioning to a self-service model for OAuth credential management, empowering developers to build and maintain integrations with greater speed and autonomy.
What is changing?
Historically, obtaining OAuth credentials to work with Squarespace APIs required manual form submissions and Zendesk tickets, often resulting in wait times of several days. With this launch, we are introducing a new "Developer Apps" tab within the Account Dashboard, allowing you to bypass manual provisioning.
Key Features
- Instant Credential Generation: Generate OAuth client IDs and secrets immediately for development and testing.
- On-Demand Secret Rotation: Securely rotate client secrets through the self-service interface to maintain high security standards without reaching out to support.
- Unified Management: Create, update, and view application details in a single dashboard.
Demo Mode and Production Reviews
To ensure platform security while maintaining developer speed, all new applications created via the self-service tool will enter Demo Mode by default.
When you are ready to take your integration live, simply request a review directly from the app details page in your dashboard.
Approval takes your app out of Demo Mode. It doesn't list your app in Squarespace Extensions, which is a separate process.
How to Get Started
- Visit the Portal: Navigate to developers.squarespace.com and select Start Building on our homepage.
- Accept Terms: You will be prompted to accept the mandatory Developer Terms of Use to unlock the new functionality.
- Manage Credentials: Access the Developers tab in your Account Dashboard to begin creating your first app.
Note for Existing Users: This change applies to new OAuth applications. Existing OAuth users who wish to utilize the self-service management screen should create a new app through the dashboard and request a review.
Thank you for building on the Squarespace platform. We look forward to seeing what you create.

Accessing Squarespace APIs using OAuth 2.0
Squarespace uses OAuth 2.0 to authorize third-party applications to integrate with Squarespace and consume Squarespace APIs.
Terms
| Client | Third-party application that needs to make Squarespace API calls. | 
| User | Squarespace customer who wants to integrate their site with a client. | 
| Confirmation page | Page created by Squarespace for the user to authorize (Allow or Deny) client access to their Squarespace account. | 
| Access token | Short-term token to make authenticated API requests. | 
| Refresh token | Long-term token to obtain new access tokens. | 
Instructions

Before a client can make Squarespace API calls, the client must be registered with Squarespace as an OAuth client. Start the Oauth client process here.
