API Accounts
BigCommerce offers a suite of APIs that let you manage store data, sign customers in, make client-side queries for product information, and write apps that integrate third-party services into store operations.
BigCommerce API accounts play a role in every authenticated request to our servers. Our API accounts come in a few different flavors to meet the needs of different use cases. For example, app API accounts work well in multi-store contexts, whereas store API accounts are a good choice for frontend applications. Some endpoints only work with one kind of API account.
For an overview of the authentication schemes that our APIs use, see the Authentication section below.
API accounts
BigCommerce offers three types of OAuth-based API accounts to developers who wish to use BigCommerce’s REST APIs: store-level credentials, app-level credentials, and account-level credentials. This section describes the difference between the three, how to obtain and revoke account credentials, and the use cases for each. It also contains a reference for available OAuth scopes and provides a compelling list of reasons to migrate from legacy API tokens to OAuth credentials.

MCP Overview
The Model Context Protocol (MCP) is an open standard that lets AI agents, such as Claude, Cursor, and ChatGPT, discover and call tools. An MCP server publishes a list of tools, each with a name, a description, and an input schema. The agent picks the right tool for a request and calls it, instead of scraping pages or calling raw APIs.
BigCommerce supports MCP in three ways. Each one serves a different kind of agent and acts with a different level of access.
The Docs MCP server is separate from these capabilities. It lets your AI tool search the BigCommerce developer documentation, and it can’t read or change store data.
Use cases
Storefront MCP
Use Storefront MCP to let an agent shop your catalog for someone: a conversational shopping assistant, a chat widget on your storefront, or a third-party AI shopping app. The agent can search products, compare options, build a cart, and hand the shopper a checkout link.
- Every store gets the storefront tools. Catalog, cart, and checkout tools work for guests, logged-in customers, and B2B buyers.
- B2B Edition stores get extra tools. Authenticated buyers can also manage shopping lists and request and work with quotes.

GraphQL Storefront API overview
BigCommerce’s GraphQL Storefront API makes it possible to power a headless storefront; see Introduction to Headless Commerce for details. The GraphQL Storefront API also lets you query storefront data from within a Stencil theme.
This graph serves as a flexible interface for building shopper experiences. For example, with the GraphQL Storefront API, it is possible to do the following:
- Query product catalog data to help shoppers find the product they’re looking for through BigCommerce’s searching, filtering, and sorting capabilities.
- Request any product’s images at any resolution.
- Ask for a signed-in customer’s details, such as name, email address, and attributes.
- Look up objects, such as categories or brands, by URL, and fetch their details.
- Create new carts, fetch existing carts, and initiate checkout.
GraphQL currently does not support sorting products based on pricing defined in Price Lists. Price based sorting methods with GraphQL will be based on prices on the product level.

Docs MCP Server
The docs site exposes a Model Context Protocol (MCP) server that AI tools can search and reference. Once connected, your AI tool can answer questions like “How does the BigCommerce checkout API work?” by pulling directly from the docs.
This server lets your AI tool search and reference the BigCommerce documentation. It can’t read or change your store, orders, catalog, or account settings. If you’re looking for an MCP server that interacts with your storefront, see the BigCommerce MCP Server. For everything else, use the REST and GraphQL APIs.
For schema-aware workflows, you can also download BigCommerce OpenAPI Specifications and add them to tools that import OpenAPI files.

Single-Click App OAuth Flow
After you install your draft app and create an app profile, you’re ready to write the code grant authorization flow that generates a unique access_token for each store that installs your app. This article covers the sequence and contents of API requests and responses in the code grant authorization flow for a BigCommerce app.
It may be more appropriate for your application to use an API client to handle this logic; see the list of BigCommerce API clients that expose OAuth-related helper methods.
Store owner access_token constraint
Typically, only store owners and authorized users can create API accounts and access_tokens for a store. However, when an app is approved to be publicly available for additional stores to install, it can generate access_tokens on behalf of store owners and authorized users.
Overview
Your app must expose a callback endpoint, GET /auth, that the merchant’s store control panel can hit to initiate the code grant authorization flow. For a list of all the callback endpoints your app can expose, both required and optional, see Single-Click App Callback Handlers.
