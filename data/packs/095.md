Workload identity federation lets a workload call the Reducto API without a long-lived API key. The workload sends a short-lived token from its platform (GitHub Actions, Kubernetes, AWS, Azure, Google Cloud and others) to Reducto. Reducto verifies the token and returns a short-lived Reducto access token. The workload uses that access token in place of an API key.
Use workload identity federation when:
- A CI workflow calls Reducto, and you do not want a Reducto API key in your repository secrets.
- A service runs on Kubernetes, a cloud VM or a serverless runtime that already has a platform identity.
- Your security team requires that no long-lived credentials sit in secret stores or environment variables.
- You want to limit Reducto access to one repository, branch, service account or cloud role.

What is MCP?
The Model Context Protocol is an open standard that lets AI agents call external tools. An MCP server exposes a set of tools (here, Reducto’s APIs) that the agent can invoke as part of its reasoning loop. You install the server once, point your client at it, and the agent figures out which tool to call and how to chain results.
If you’ve never used MCP before, the mental model is simple: you describe what you want in plain English, and the agent decides which Reducto tool to call, when to upload a file, and how to pass results between steps.

The token exchange endpoint trades a subject token from your identity provider for a short-lived Reducto access token. It implements OAuth 2.0 Token Exchange (RFC 8693). For concepts and setup, see Workload identity federation.
The Reducto Python and Node.js SDKs call this endpoint for you. Call it directly when you use another language or want to manage the access token yourself.
Endpoint
Use the host of your region: platform.reducto.ai (US), eu.platform.reducto.ai (EU) or au.platform.reducto.ai (AU). The endpoint accepts application/json or application/x-www-form-urlencoded bodies. It needs no Authorization header.

# Reducto Authentication

Reducto supports direct HTTP signup for a new user at a new company. It grants the standard 15,000 free credits and an API key. The human supplies an email, their name, a verification code, and explicit agreement to the terms. No CLI or browser cookies are needed.

Use the approved secret store or process environment; do not print its contents. If REDUCTO_API_KEY exists, check it with GET https://platform.reducto.ai/jobs?limit=1 and Authorization: Bearer $REDUCTO_API_KEY. A 200 response means setup is done. Invalid saved keys go to Studio for recovery, not a new signup. Retry service failures without creating an account.

Then ask the human for whatever is still missing plus terms agreement, together: “Do you agree to [Reducto's terms](https://reducto.ai/terms) and acknowledge the [privacy policy](https://reducto.ai/privacy)? Agreeing authorizes me to create the account and receive an API key on your behalf.” Add the code, name, and first document to the question only if you could not obtain them.

| HTTP | error.code | Agent action |
| --- | --- | --- |
| 400 | invalid_input | Show the field and message; ask for corrected input. If error.restart_required is true, user creation was rejected: correct the fields and start a new code request after the cooldown. Otherwise retry the request, preserving any already accepted verification data. |
| 400 | invalid_code | Ask the human to check the code. Never guess. |
| 410 | verification_expired | The token/code expired, was superseded, or exhausted five attempts. Request a new code after the cooldown. |
| 403 | signup_restricted | Show the email-policy message in the terminal and ask for a different email. Retry signup with that email; do not bypass restrictions. |
| 409 | studio_required | Stop automated signup and show the human error.message with studio_url. They can sign in or select Join or Request access for a listed organization in Studio. This also covers uncertain provisioning or expired key delivery. |
| 429 | rate_limited | Wait Retry-After seconds before retrying. |
| 503 | temporarily_unavailable | Retry the same request after Retry-After; for an interrupted initial code request, respect the resend cooldown. |
