## Plan limits

All requests besides [free test queries](./free-test-queries.md) and the *Rank Tracker*, *Management*, *Public* and *some other* endpoints consume **API units**. The cost depends on the number of rows in a response and the fields requested. The minimum cost for any request is **50 units**. If an endpoint is free, you'll see a note about that on its documentation page; otherwise, it consumes units.

[Eligible paid plans](https://ahrefs.com/pricing) include a monthly API unit allowance. On plans that support pay-as-you-go usage, additional units are automatically charged once the included limit is exceeded.

See also: [Pricing page](https://ahrefs.com/pricing) and [Account settings / Limits & usage](https://app.ahrefs.com/account/limits-and-usage/web).

## API keys

To send requests to Ahrefs API, you'll need an API key. Only workspace owners and admins can create and manage API keys. This can be done in [Account settings / API keys](https://app.ahrefs.com/account/api-keys).

# API keys creation and management

You'll need an API key to send requests via Ahrefs API v3. Provide it in the Authorization header when making requests: `Authorization: Bearer YOUR_API_KEY`.

## Creating API keys

Create and manage existing API keys in [Account settings / API keys](https://app.ahrefs.com/account/api-keys). Note that only workspace owners and admins have access to this section.

You can create up to 1,000 API keys. When creating or editing a key, choose an expiration date between today and 10 years from today. After that date, the key becomes inactive. You can see the expiration date for each key and who created it on this page.

A key will also be invalidated if the user who created it is removed from the workspace.

![](<../images/API keys1.png>)

## Controlling usage

To control the monthly usage of API units in your workspace, limit the usage of particular API keys in [Account settings / API keys](https://app.ahrefs.com/account/api-keys).

![](<../images/API keys2.png>)

If your subscription plan allows pay-as-you-go charges, you can also limit the maximum number of API units that can be added on a pay-as-you-go basis or disable pay-as-you-go API units altogether in [Account settings / Limits & usage](https://app.ahrefs.com/account/limits-and-usage/web).

# ChatGPT Web

### Note on ChatGPT support

> **INFO**
> Full support for MCP client access is currently in **beta** in ChatGPT. At the moment, it's only available in **Developer mode** for **Pro and Plus accounts on the web.**

While it's in beta, we recommend being as **explicit and precise as possible** in your prompts. For example:

- Mention the **Ahrefs MCP** directly.
- Specify the **tool or endpoint** to use.
- Indicate which **fields to pull** and how to **sort the results.**
- Excplicitly ask ChatGPT **not to use the web search.**

Better results often come from structured prompts like this:

*"Using the Ahrefs MCP connector and the `keywords-explorer-matching-terms` action, pull the top 10 keywords related to "marketing" in Brazil, sorted by search volume."*

instead of a vague prompt like:

*"What are the top keywords related to marketing in Brazil?"*

For the latest details, see the official [ChatGPT Developer Mode docs](https://platform.openai.com/docs/guides/developer-mode)

# OAuth guide

All API calls require authorization and are made **on behalf of an authorized Ahrefs user**. To do this, your app must obtain an API **access token** for that user.

Ahrefs Connect uses **OAuth 2.0 Authorization Code Flow with Proof Key for Code Exchange (PKCE)**. The process has two main steps:

## 1. Authorize the application

Redirect the user to:
```html
https://app.ahrefs.com/web/oauth/authorize?response_type=code&client_id={client_id}&scope=apiv3-integration-apps&redirect_uri={redirect_uri}&code_challenge={code_challenge}&code_challenge_method=s256&state={state}
```

- `{client_id}` : URL-encoded Client ID from **Ahrefs Connect** section in your [Account settings](https://app.ahrefs.com/account/my-account).
- `{redirect_uri}` : URL-encoded Redirect URI you’ve registered in the same section.
- `{code_challenge}` : Derived from a **code verifier** using the S256 method:
    - Generate a **code verifier** — a random string of 43–128 characters using a cryptographically secure generator. Allowed characters: `[A-Z] [a-z] [0-9] - . _ ~` (see [RFC7636 Section 4.1](https://datatracker.ietf.org/doc/html/rfc7636#section-4.1)).
    - Compute the **SHA-256** hash of the code verifier.
    - Base64-URL-encode the hash.
    - Use this encoded value as the `code_challenge` (see [RFC7636 Section 4.2](https://datatracker.ietf.org/doc/html/rfc7636#section-4.2)).
- `{state}` : Generate an opaque value to maintain state between the request and callback. The authorization server will include this value when redirecting the user back to your app. (see [RFC6749 Section 4.1.1](https://datatracker.ietf.org/doc/html/rfc6749#section-4.1.1))

```json
{
    "access_token": "\<token to use in API requests>",
    "expires_in": \<lifetime of the access token in seconds>,
    "token_type": "Bearer",
    "scope": "apiv3-integration-apps"
}
```

- **No refresh tokens are issued.**
- Access tokens are valid for **1 year**. After expiry, the user must **reconnect (re-authorize)** via OAuth.

> **INFO**
> **Security note:**
> - **Never** expose `access_token` to end users, either during authorization or later (in UI, logs, URLs, or client-side code).
> - For **web apps**, store `client_secret` **server-side only**.
> - You will need to demonstrate secure token handling as part of the [Approval process](./approval-process.md).
