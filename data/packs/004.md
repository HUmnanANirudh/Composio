# Generate an API key

Easily generate API keys for your Attio workspace.

> Available on all plans.
>
> **Admins** can create and manage API keys.

API keys allow you to connect external tools and services to your workspace with secure, scoped access. You can generate access tokens to read, create, or update data in Attio, making it easy to build custom integrations, automate workflows, and sync information across platforms.

## Generate an API key

In order to generate an API key for your workspace, you must be an admin. If you're not an admin for your workspace, you can ask an admin to complete the following steps:

- From the dropdown beside your workspace name, click **Workspace settings**.
- Click the **Developers** tab.
- Click **+ New access token**.
- Give your new access token a name.
- Set the appropriate **Scopes** for the token.

Treat access tokens like passwords, as they contain sensitive information. [Learn more about keeping your data safe](https://attio.com/help/apps/other-apps/generating-an-api-key#keeping-your-data-safe).

## Manage API keys

Once you've created access tokens, admins can manage them from the **Developers** page in Workspace settings.

Your API keys should be treated as highly sensitive information - think of a token like a password. You should only give tokens to services you fully trust.

# Authorize

#### Query Parameters

**client\_id** `string` *required*

Your app's client ID. You can find this in your app's settings pages at
[build.attio.com](https://build.attio.com).

**response\_type** `string` *required*

The response type. This should always be `"code"`.

**redirect\_uri** `string` *required*

The URL to redirect to after the user authorizes access to your app. This URL must exactly match
one of the registered redirect URLs in your app's settings pages at
[build.attio.com](https://build.attio.com).

**state** `string`

A random string to prevent CSRF attacks. Set this when starting the OAuth flow and verify it
matches when the user is redirected back to your app.

**token\_level** `string` (default: workspace)

The [level](https://docs.attio.com/rest-api/guides/authentication.md#token-levels) of the access token, either
`"workspace"` or `"user"`. A `"user"` token requires `code_challenge` and `code_challenge_method`.

**code\_challenge** `string`

A [PKCE](https://datatracker.ietf.org/doc/html/rfc7636) code challenge: the base64url-encoded
SHA-256 hash of a code verifier. Required when `token_level` is `"user"`. Pass the code verifier
as `code_verifier` when you exchange the code at the [token endpoint](https://docs.attio.com/docs/oauth/token.md).

**code\_challenge\_method** `string`

The PKCE code challenge method. This should always be `"S256"`. Required when `code_challenge` is
set.

#### Response

**302** `Redirect`

After the user approves the connection, they are redirected to the `redirect_uri` with a `code`
query parameter. If provided, the original `state` is also included.
