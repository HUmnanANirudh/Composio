Authentication
How to authenticate with Pylon's API
The Pylon API uses Bearer authentication. This means you’ll need to pass your API token in the header of your request:
Authorization: Bearer <token>
API regions
Pylon’s API is available in two regions. Use the base URL that matches where your Pylon tenant is hosted:
- US region: https://api.usepylon.com
- EU region: https://api.eu.usepylon.com
Both regions use the same API endpoints and authentication. Configure your integration to use the region where your Pylon tenant is hosted.
You can tell a token's region from its prefix:

Tokens created before prefixes were introduced have no prefix. Sending a token to the other region's API returns 401 with the wrong_region_token error code, and the message names the correct URL.
Once you've created a token, call the /me endpoint to retrieve details about your organization and confirm your token works.

Pylon MCP
Expose Pylon data to AI tools and assistants via Model Context Protocol.
Pylon MCP Server
The Pylon MCP Server exposes Pylon data to AI tools that support the Model Context Protocol (e.g. Claude, ChatGPT, Cursor). AI tools authenticate with OAuth or an API token and can read and update issues, accounts, contacts, knowledge base articles, tasks and projects, triggers, and more within the authenticated identity's permissions.
- Server URL (US): https://mcp.usepylon.com
- Server URL (EU): https://mcp.eu.usepylon.com
- Auth: OAuth 2.0 or an API token. Actions are performed as the signed-in user or the token's identity, with that identity's current role and permissions.
- Transport: Streamable HTTP (stateless; no server-side sessions).

Open Settings > AI Controls > MCP Server in Pylon. Copy your workspace's regional MCP URL from Installation and use it in your AI tool. For client-specific instructions, see connecting to the Pylon MCP Server.

Webhooks
Receive webhooks for various events happening in Pylon.
This page covers webhooks that Pylon sends to you.
Setup
- Go to Settings > Integrations & dev > Webhooks and click Create Webhook.
- Enter a Name and the Target URL, and pick the HTTP method (POST by default; GET, PUT, PATCH, and DELETE are also available).
- Optionally, add Custom headers, for example an Authorization header with a Bearer token. Turn on Secret for a header to encrypt its value and hide it after saving.
- Click Create and copy the webhook secret. Pylon shows it only once. You need it to verify deliveries.
The target must be a public http or https URL. Private and internal network addresses are blocked. If your endpoint sits behind a firewall, allowlist Pylon's IP addresses for your region.
Payload
In the Send webhook action, write the request body in JSON payload. Type { to insert variables such as {{ issue.id }} or {{ issue.title }}. The variables you can use depend on the trigger's object. See Template variables for the full list, including tags, the latest message, and its author.

How do I create a Pylon API token?
Applies to: Pylon API access
To create a Pylon API token, sign in as a user with permission to manage API tokens, then open Settings → API Tokens. If you do not see that page, ask a workspace admin to create the token or update your access.
- Open Settings → API Tokens.
- Select Create.
- Enter a token name, then finish creation.
- Copy the token immediately and store it in a secure location. Pylon only shows the full token value once.
Use the token to authenticate Pylon API requests with a Bearer header:
- Authorization: Bearer <token>
If you need read-only access, a workspace admin should choose an appropriate role for the token when creating it.
