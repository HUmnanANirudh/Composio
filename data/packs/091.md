[S4] https://developers.google.com/notebook/docs/authentication (official)
The Gemini Notebook API uses [OAuth 2.0](https://developers.google.com/identity/protocols/oauth2.md.txt) to
authenticate requests on behalf of a Google user. Every request must include an
OAuth 2.0 Bearer token in the `Authorization` HTTP header. The API doesn't
accept API keys.

- **Create or select a Google Cloud project.** You enable the API, configure the OAuth consent screen, and create OAuth clients in this project. To create a project, see [Create a Google Cloud project](https://cloud.google.com/resource-manager/docs/creating-managing-projects).
- **Use a personal Google Account.** During the Public Preview, the Gemini Notebook API is only available for personal Google Accounts. Requests authenticated with a Google Workspace account fail with `403 PERMISSION_DENIED` (`WORKSPACE_ACCOUNT_NOT_SUPPORTED`).
- **Sign in to Gemini Notebook once.** The API reads and writes the notebooks of the authorizing user, so each Google Account must have signed in to [Gemini Notebook](https://notebook.google.com) at least once before calling the API. If an account has never signed in to Gemini Notebook, `CreateNotebook` requests fail with `404 NOT_FOUND` (`Account not found for user.`).

## OAuth 2.0 scopes

Requests must be authenticated with an OAuth 2.0 token granted one of the
following scopes:

1. **Enable the API** : In the [Google Cloud Console](https://console.cloud.google.com/apis/library/notebook.googleapis.com), select your Google Cloud project and enable the **Gemini Notebook API** (`notebook.googleapis.com`).
2. **Configure the OAuth consent screen** : Go to the [Google Auth Platform branding page](https://console.cloud.google.com/auth/branding) to configure your app details, and add the `https://www.googleapis.com/auth/notebook` scope on the [Data Access page](https://console.cloud.google.com/auth/scopes).
3. **Create an OAuth 2.0 client ID** : Go to the [Clients page](https://console.cloud.google.com/auth/clients), click **Create client** , and select your application type (for example, **Desktop app** or **Web application** ). Download the client configuration JSON file as `client_secret.json`.
4. **Request an access token and call the API** : Follow the [OAuth 2.0 flow](https://developers.google.com/identity/protocols/oauth2.md.txt#scenarios) for your application type to obtain an access token and pass it in the `Authorization: Bearer` header:

[S6] https://www.kortex-notebooklm.com/blog/notebooklm-mcp (official)
> **Key Takeaways**
> - There is **no official Google Gemini Notebook MCP server**; a request for one on the google/mcp repo is open ([GitHub](https://github.com/google/mcp/issues/19), 2026).
> - MCP is a real, fast-growing standard. By its first anniversary the official registry held nearly 2,000 entries with 407% growth since September 2025 ([MCP Blog](https://blog.modelcontextprotocol.io/posts/2025-11-25-first-mcp-anniversary/), 2025).
> - Community servers work via browser automation or undocumented APIs, not a public API. The best-known, PleasePrompto/notebooklm-mcp, is archived.
> - Google's only documented Gemini Notebook API is **enterprise-only** through Gemini Enterprise; consumer accounts can't use it.
> - **Kortex MCP comes with Kortex Pro and Lifetime:** one endpoint, 145+ notebook tools, each call run by the extension in your own browser (Kortex MCP docs, 2026).

The other approach skips the browser and calls Google's internal endpoints directly. The gemini-notebook-mcp-cli project, which notably has even more stars (6,200+), says its internal APIs "are undocumented and may change without notice" and "require cookie extraction from your browser" ([GitHub](https://github.com/jacob-bd/gemini-notebook-mcp-cli), 2026). Different plumbing, same fragility, and the same cookie risk as a result. Our [Kortex MCP vs notebooklm-mcp-cli comparison](/blog/kortex-mcp-vs-notebooklm-mcp-cli) puts sign-in, clients and price side by side.

**Kortex MCP** is a hosted MCP server, included with Kortex Pro and Lifetime. One endpoint gives Claude, ChatGPT, Cursor and other MCP clients 145+ notebook tools, and each call runs through the Kortex extension in your own Chrome instead of a stealth browser ([Kortex MCP docs](/docs/mcp-server), 2026). Want in?

- **OAuth sign-in.** Paste the URL into your client. It opens a Kortex consent page, you sign in, and you're connected.
- **API key.** Create a key in the Kortex popup and send it as `Authorization: Bearer kx_mcp_...`. Handy for CI or a machine without a browser, and the [API key docs](/docs/mcp-api-key) show where to create one and how to scope it.
- **Read-only keys.** A key can be limited to read-only tools, so a client can ask notebooks but not change them. Start there, then move up when you need writes.
