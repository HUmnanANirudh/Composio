[S1] https://vercel.com/docs/rest-api (official)
Interact programmatically with your Vercel account using the SDK or direct HTTP requests. You can deploy new versions of web applications, manage custom domains, retrieve information about deployments, and manage secrets and environment variables for projects.
The API supports any programming language or framework that can send HTTP requests.
The API is exposed as an HTTP/1 and HTTP/2 service over SSL. All endpoints live under the URL https://api.vercel.com and follow the REST architecture.
Vercel Access Tokens are required to authenticate and use the Vercel API. Include the token in the Authorization header:
Authorization: Bearer <TOKEN>
Create and manage Access Tokens in your account settings.
By default, a request with a full-account token targets your default team. To access resources owned by another team, append the Team ID as a query string:
https://api.vercel.com/v6/deployments?teamId=[teamID]
The API limits the number of calls you can make over a period of time. Rate limits are specified via response headers: X-RateLimit-Limit, X-RateLimit-Remaining, and X-RateLimit-Reset. See the limits documentation for details.
Browse all available REST API endpoints grouped by category.

const result = await vercel.projects.getProjects({ limit: '1' });
const projects = Array.isArray(result) ? result : result.projects;

if (projects.length === 0) {
 console.log('Success: no projects in this token scope');
} else {
 const project = projects[0];

terminalnode index.mjs If the token scope contains a project, the script prints a project name and ID: Success: my-project (prj_xxxxxxxxxxxxxxxxxxxxxxxx) If the scope contains no projects, the script still confirms that the request succeeded: Success: no projects in this token scope
The token scope determines which projects GET /v10/projects can return:
| Token scope | Request target | teamId or slug behavior | 
|---|---|---|
| Full Account | Your default team by default, or another team you belong to | Omit both to target your default team. Pass either value to target another team. | 
| Team | Projects in the token's team | Omit both. Vercel infers the team from the token. | 
| Project | The token's single project | Omit both.

[S6] https://vercel.com/docs/cli/mcp (official)
vercel mcp
The vercel mcp command helps you set up MCP clients (Claude Code, Claude.ai and Claude for desktop, Cursor, and VS Code with Copilot) to use Vercel MCP, Vercel's hosted Model Context Protocol endpoint at https://mcp.vercel.com. For Claude Code, the command adds Vercel MCP to the client. For Cursor and VS Code with Copilot, it opens the client's one-click installer for Vercel MCP, and you follow the prompts there to complete the setup. For Claude.ai and Claude for desktop, it prints manual setup instructions for adding a custom connector. To set up another client, see Vercel MCP setup.
By default, clients are pointed at the shared endpoint. With --project, they're pointed at a project-specific URL (https://mcp.vercel.com/<team>/<project>) so the MCP session is scoped to the linked Vercel Project.
The command does not deploy any MCP server of your own. It only adjusts the client-side configuration on your machine.
vercel mcp [options]
By default, vercel mcp runs an interactive picker that lets you choose which MCP clients to set up. In non-interactive environments such as CI, you must pass --clients to skip the picker.
After the command finishes, complete any authentication that the client asks for. In Claude Code, run the /mcp command to authenticate.
vercel mcpvercel mcp --clients "Cursor,VS Code with Copilot"vercel mcp --project
These are options that only apply to the vercel mcp command.
The --clients option accepts a comma-separated list of MCP clients to set up. In interactive mode, it skips the client picker. In non-interactive mode (for example, CI), --clients is required.
Supported values:
- Claude Code
- Claude.ai and Claude for desktop
- Cursor
- VS Code with Copilot
vercel mcp --clients "Cursor,VS Code with Copilot"
The --project option sets up project-specific MCP access for the currently linked project instead of global configuration. If your directory isn't linked to a project, run vercel link first.
vercel mcp --project

For more information on global options and their usage, refer to the options section.

If a request with a token fails, read the error object in the response body to find the cause:
| Response | Cause | Fix | 
|---|---|---|
| 403 with "invalidToken": true | The token is wrong, expired, or deleted. | Check that the header reads Authorization: Bearer <token> and that the token still appears on the Account Tokens page. If you've lost the token, create a new one. | 
| 403 with "missingToken": true | The request has no Authorization header, or the header isn't in the form Bearer <token>. A common cause is an environment variable that's empty in the current shell. | Check that the header reads Authorization: Bearer <token>. Run echo "${VERCEL_ACCESS_TOKEN:+set}" to confirm the variable is set, then send the request from the same shell. | 
| A team's resources are missing, or the request is denied, with a full-account token | A full-account token targets your default team unless you specify a team. | Add teamId or slug to the request. |
