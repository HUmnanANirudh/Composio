# Authentication

- An [Access Token](#access-tokens) is for if you're using the API to access data in **your own** Intercom workspace, in other words, building a private app.
- [OAuth](#oauth) is for if you're building a public app that accesses **other people's** Intercom data.

![A image showing the use of a personal access token to work with data on the Intercom API](/content-assets/pat-flow-ac75455ec917a997.png)

You can find your Access Token in the **Configure > Authentication** section in your app within the [Developer Hub](https://app.intercom.io/a/apps/_/developer-hub/app-packages).

An Access Token is issued to the teammate who installed the app on the workspace, or who last regenerated the token. Its access to conversations is limited by that teammate's conversation access, in addition to the app's scopes. See [Conversation access is limited by the installing teammate](/docs/build-an-integration/learn-more/authentication/oauth-scopes#conversation-access-is-limited-by-the-installing-teammate).

Your Access Token can give access to your private Intercom data and should be treated like a password. If an app provider asks you for your Access Token, please do not provide it. Instead, let us know - apps are required to use OAuth rather than asking users for Access Tokens.

![OAuth Flow](/content-assets/x8kDkKlSQ424LXUZ7Sh1_OAuth_cropped-b71f37dc5ebde851.png "OAuth Flow")

To set up and test the OAuth installation flow in your development workspace by [following this tutorial](/docs/build-an-integration/learn-more/authentication/setting-up-oauth).

Asking your users for their Access Tokens rather than implementing OAuth is against our terms of service and may result in your API access being revoked.

Once you have a token, whether an access token or a token via the OAuth process, simply provide it as an `Authorization:Bearer` header in your requests, as shown below. If you want to go deeper on how the `Authorization:Bearer` header works please check out the [full spec here](https://tools.ietf.org/html/rfc6750).

```bash
$ curl \
-s https://api.intercom.io/users/5321a20f72cdbb4192000013 \
-H 'Authorization:Bearer <access_token>' \
-H 'Accept:application/json'
```

Alternatively, helper functions are provided in some of our SDKs to authorize via Access Tokens. This means you don't need to specify the header explicitly - it's all done under the hood.

Should I use the /users or /contacts endpoint?
Use /contacts. In the current API, users and leads are both contacts, and you create or update them with the Create a contact (POST /contacts) and Update a contact (PUT /contacts/{id}) endpoints. POST /users is a legacy 1.x endpoint and won't work with current API versions.
How do I create a contact without an email address?
A contact needs at least an email or an external_id. To create a user without an email, send your own unique identifier for them as external_id. In the /contacts endpoints this field is called external_id, not user_id. Sending user_id without an email returns the error either_email_or_user_id_present validation failed.
POST https://api.intercom.io/contacts
{
"external_id": "cust_001",
"name": "Jane Doe",
"custom_attributes": {
"Currency": "EUR"
}
}
Any custom attributes you set must already exist in Settings > Data > People, otherwise the request returns an error saying the attribute doesn't exist.

# OAuth Scopes

When you configure OAuth you will need to define the OAuth scopes, and these will be reviewed when you [submit your app for approval](/docs/publish-to-the-app-store/review-publish-your-app). This guide will help you understand what OAuth scopes are, which ones are available, and how to choose them.

## What are OAuth scopes?

OAuth scopes, or permissions, let you specify exactly what types of data your app can access within an Intercom workspace and actions that it can take with the workspace's data.

You select OAuth scopes when you are configuring OAuth in your [Developer Hub](https://app.intercom.com/a/apps/_/developer-hub).

![OAuth Scopes Settings in the Developer Hub](/content-assets/oauth_scopes-4055ee7a8c27a5ef.png)

## Why are OAuth scopes important?

OAuth scopes are important because they define the level of access your app has to specific pieces of customer data. For the security of our customers, Intercom ensures that public apps only access resources necessary to the functionality of the app.

## Available OAuth scopes

- For a public app, that is the teammate who authorized your app through OAuth.
- For a private app, that is the teammate who installed the app on the workspace, or who last regenerated its Access Token.

- Requests that act on a single conversation outside the teammate's access return a `403` error with the code `token_unauthorized`. This applies to retrieving, updating, deleting, replying to, managing, merging, converting and redacting a conversation, to attaching or detaching its contacts and tags, and to the other endpoints that act on a single conversation.
- [List](/docs/references/rest-api/api.intercom.io/conversations/listconversations) and [search](/docs/references/rest-api/api.intercom.io/conversations/searchconversations) return only the conversations the teammate can access.
- `conversation.*` webhook topics are delivered only for conversations the teammate can access.

```json
{
  "type": "error.list",
  "request_id": "...",
  "errors": [
    {
      "code": "token_unauthorized",
      "message": "Not authorized to access this conversation"
    }
  ]
}
```
